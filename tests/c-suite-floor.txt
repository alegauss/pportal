# PP439: the size of the oracle.
#
# How many munit cases the C suite runs. ctest reports the whole suite as ONE test, so
# "100% tests passed out of 1" is the same sentence whether 145 cases ran or 7 of them
# stopped existing. munit prints its own "N of N tests successful" and ctest throws that
# away on a green run, which is what this file and scripts/test-windows.sh restore.
#
# The number below may RISE and may not FALL. test-windows.sh fails either way:
#   below it - a suite got smaller. Something stopped compiling in, and the mechanism
#              is real: CHIAKI_ENABLE_FFMPEG_DECODER is a tri_option defaulting to AUTO,
#              so a configure that cannot find ffmpeg sets it OFF rather than failing,
#              ffmpegdecoder.c is not built, and its seven cases quietly do not exist.
#   above it - tests were added, so raise this line in the same commit, or the floor
#              quietly loosens by exactly what was just gained. It is PP38's ratchet the
#              other way up, and for the same reason.
#
# `test.cmd` prints the count on every run now, so the number to put here is the one it
# just printed. A configure without ffmpeg legitimately runs 138: that is not a lower
# floor, it is a different build, and lowering this line to accommodate it would delete
# the only thing that notices the seven going missing on a machine that HAS ffmpeg.
#
# 145 on 2026-08-27, when the count was first taken: 16 suites, of which the parameterised
# ones are /http/response_parse over two line endings and /fec/fec over 64 recorded frame
# buffers - 64 of the 145, and the largest single thing the oracle knows.
#
# 147 on 2026-08-30: PP72 added the two decoderchoice cases its decision rests on - that an
# explicit d3d11va outranks the cuda preference, and that the preference fires at three
# arrivals rather than the one its design named.
#
# 149 the same day: PP76's readable half added the two over chiaki_session_baseline_decoder_drops
# - that the decoder's own loss is the difference between the record's two counters, and that
# the difference never wraps when the receiver ends a session ahead of the presenter.

# 77 on 2026-09-06: PP696 took the frame path out of the build, and the C suite's four files went
# with it. 72 cases left - 64 of them the parameterised /fec/fec run over the recorded frame
# buffers, which was the largest single thing this oracle knew, plus frameprocessor.c's three,
# allocbudget.c's three and videoreceiver.c's two.
#
# THIS IS THE ONE FALL THIS FILE ALLOWS, and it is allowed because the cases did not stop being
# checked - they moved. FecCodecTests, FrameAssemblerTests, ManagedVideoReceiverTests and
# AllocBudgetTests are their counterparts, and PP669 asserts that each of the four has one. A fall
# with no such answer is the thing the paragraph above refuses.
77
