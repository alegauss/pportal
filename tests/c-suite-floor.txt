# PP439: the size of the oracle.
#
# How many munit cases the C suite runs. ctest reports the whole suite as ONE test, so
# "100% tests passed out of 1" is the same sentence whether 145 cases ran or 7 of them
# stopped existing. munit prints its own "N of N tests successful" and ctest throws that
# away on a green run, which is what this file and scripts/test-windows.sh restore.
#
# The number below may RISE and may not FALL. test-windows.sh fails either way:
#   below it - a suite got smaller. Something stopped compiling in, and the mechanism
#              is real: CHIAKI_ENABLE_FFMPEG_DECODER is a tri_option defaulting to AUTO,
#              so a configure that cannot find ffmpeg sets it OFF rather than failing,
#              ffmpegdecoder.c is not built, and its seven cases quietly do not exist.
#   above it - tests were added, so raise this line in the same commit, or the floor
#              quietly loosens by exactly what was just gained. It is PP38's ratchet the
#              other way up, and for the same reason.
#
# `test.cmd` prints the count on every run now, so the number to put here is the one it
# just printed. A configure without ffmpeg legitimately runs 138: that is not a lower
# floor, it is a different build, and lowering this line to accommodate it would delete
# the only thing that notices the seven going missing on a machine that HAS ffmpeg.
#
# 145 on 2026-08-27, when the count was first taken: 16 suites, of which the parameterised
# ones are /http/response_parse over two line endings and /fec/fec over 64 recorded frame
# buffers - 64 of the 145, and the largest single thing the oracle knows.
#
# 147 on 2026-08-30: PP72 added the two decoderchoice cases its decision rests on - that an
# explicit d3d11va outranks the cuda preference, and that the preference fires at three
# arrivals rather than the one its design named.
#
# 149 the same day: PP76's readable half added the two over chiaki_session_baseline_decoder_drops
# - that the decoder's own loss is the difference between the record's two counters, and that
# the difference never wraps when the receiver ends a session ahead of the presenter.
#
# Still 149 on 2026-09-06, and PP786 is why the number below did not move. Two deletions are
# arranged for and neither has landed, so what is recorded here is the arithmetic each one owes:
#
#   PP696 takes the frame path's four test files and 72 cases with them - 64 of those are
#         /fec/fec parameterised over the recorded frame buffers.
#   PP27  takes takion's three and 9 cases: /takion runs 4, /reorder_queue 2, /alloc_budget 3.
#
#   allocbudget.c is in BOTH lists. It links frameprocessor.c and videoreceiver.c and it calls
#   chiaki_takion_v9_av_packet_parse and takion_handle_packet_av, so it leaves on whichever
#   deletion lands first and the second one takes none of its three. Together they cost 78 and
#   NOT 81, and a floor lowered by 81 would sit three below what the suite still runs - which is
#   the one failure this file exists to prevent, arriving through the arithmetic rather than
#   through a build.
#
#   So: 149 today, 77 after PP696 alone, 140 after PP27 alone, 71 after both.
#
# 71 on 2026-09-09, and BOTH LANDED IN ONE COMMIT - which is the branch of that arithmetic nobody
# expected to take. PP27's flip could not leave the frame path behind: videoreceiver.c is the only
# caller of stream_connection_send_corrupt_frame and its idr_request twin, so the linker made the
# two deletions one. Twelve library files and six test files went together.
#
# THE PREDICTION HELD EXACTLY, and that is worth recording rather than assuming it always will.
# PP786 wrote "71 after both" from reading the suites, and the suite ran 71 - so the allocbudget
# subtlety it was written for, the three cases counted once rather than twice, was right.
#
# What is gone is 78 cases of oracle, and the loss is not what it looks like. 64 of them are
# /fec/fec over the recorded frame buffers, and those buffers did not go anywhere: FecCodecTests
# runs the same corpus through the managed decoder on every build, and PP842 recorded what the C
# answered for them before it left. What a C case bought that a managed one does not is a second
# implementation - and that is the trade PP27 was filed to make, priced here rather than implied.
71
