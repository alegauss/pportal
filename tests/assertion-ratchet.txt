# PP38: the ratchet.
#
# How many SHIPPED tasks no assertion mentions. The non-goal says no line ships without an
# assertion that fails without it; this is what makes that a gate rather than a sentence.
#
# The number below may FALL and may not RISE. AssertionRatchetTests fails either way:
#   above it - a task shipped with nothing testing it, and the commit that did it is the
#             cheapest place to fix that
#   below it - the debt was paid, so lower this line in the same commit, or the ratchet
#             quietly loosens by exactly what was just gained
#
# `ChiakiNg.exe --ratchet` (PP305) lists what is owed, each id beside the ledger's own
# sentence for it - which is how to tell a task with no test from one whose tests were
# written under the id it continued. The second kind is paid by naming both ids.
#
# 97 was the debt on 2026-08-22, when the count was first taken: 283 tasks had shipped and
# 186 were named by something that runs. It is not a target and not an allowance. 96 is where
# PP305 left it, having found PP300's assertions already written under PP29.
#
# PP307 read all 96 against the git history and they are not one debt. Asking, for each id,
# whether the commit that shipped it also touched an assertion file:
#
#   75  shipped WITH a test, in the same commit, named under another id. PP208's assertions
#       are HolepunchIdentifiersTests and PP204's are PortGuessingTests - written while the
#       work was another task's, exactly as PP300's were. Paying one is naming both ids.
#   12  shipped with no test, and eleven of them could not have had one: PP56, PP67, PP74 and
#       PP75 changed the gates themselves, and PP47, PP48, PP61, PP62, PP65, PP66 and PP71
#       are measurements. PP225 is the single CODE change in this whole list that shipped
#       with nothing asserting it.
#    9  shipped under a commit scope that is not the task id - feat(spike), docs(roadmap) -
#       so no history join can see them. PP39 to PP46, which is the telemetry baseline.
#
# So the honest size of what the non-goal was protecting against is ONE, not ninety-six. The
# number below is still 96 because that is what the id join counts, and the id join is what
# the gate can check without reading git. PP308 is whether it should.
#
# PP310: the other door. A task whose output is prose has nothing to assert, so it raises the
# count and the count may not rise - PP307 could not ship at all. An `exempt` line below takes
# one such task out of the count, and the REASON is what makes it a record rather than a
# loophole: no reason, no exemption, and every line of it is read in the diff that adds it.
#
# exempt PP307 - a pass over a list; its whole output is the split written above.
#
# PP315: the twenty that could not have had a test, each said rather than counted.
#
# Four changed the gates themselves, where the gate IS the assertion - a test asserting that
# a build script builds is the build script:
# exempt PP56 - compile.cmd builds chiaki-unit; the suite linking at all is the assertion.
# exempt PP67 - test.cmd launches the suite; what it proves is that the suite runs.
# exempt PP74 - compile.cmd builds app/; the .NET host compiling is the assertion.
# exempt PP75 - test.cmd runs the host's selftest; the selftest running is the assertion.
#
# Sixteen are measurements, whose deliverable was a number in a report and not a behaviour.
# A test over one would assert that this machine still measures what it measured:
# exempt PP39 - the baseline of the four counters this build already draws on screen.
# exempt PP40 - a measurement; its result is the number it reported.
# exempt PP41 - a measurement; its result is the number it reported.
# exempt PP42 - a measurement; its result is the number it reported.
# exempt PP43 - the two present paths measured before PP9 committed to one.
# exempt PP45 - a measurement; its result is the number it reported.
# exempt PP46 - the startup and installer deltas; the delta is the deliverable.
# exempt PP47 - an evaluation: DLSS needs inputs a decoded stream does not carry.
# exempt PP48 - whether preferring the cuda decoder helps, which is a number.
# exempt PP54 - a measurement; its result is the number it reported.
# exempt PP58 - the airspace path's halved frame rate, measured and unexplained.
# exempt PP61 - a fix to the startup harness in spike/, which the suite does not build.
# exempt PP62 - no published Windows release carries Chromium, measured.
# exempt PP65 - d3d11va's decode submission stall, measured as a percentile.
# exempt PP66 - the decode-path spike's result.json naming its adapter.
# exempt PP71 - the cuda decoder's send percentile against d3d11va's.
#
# 95 is where PP309 left it, having written the assertions PP225 shipped without - the one
# code change in the port of which that was true, and the whole of what the split above found.
#
# PP314 took it to 32. Not by writing tests: by recording, in tests/assertion-index.txt, the
# assertion file each task's OWN shipping commit carried - which is the same claim as an id in
# a summary, made once where it can be checked instead of edited into sixty files. 63 lines,
# generated from git rather than typed.
#
# PP315 took it to ZERO, and zero is the number this file was for. 75 index lines and 21
# exemptions - each of the exemptions a sentence, below - and not one test written to move it,
# because not one of the 96 was a task that needed a test written. That was PP307's finding
# and this is it applied.
#
# From here the ratchet does what PP38 built it for: the next task that ships with nothing
# asserting it takes this to 1, and the suite goes red on the commit that did it.
