`ChiakiNg.exe` opens the console list when it is given no flag — the consoles on your network,
with a Connect on any that is registered. Every flag below is declared in one list in
`app/Session/HostCommandLine.cs`, and a name it does not declare is refused rather than ignored —
a mistyped flag does not silently open the window.

Both tables are generated from that list at build time. If a flag is renamed in the
application, the rename lands here in the same commit.

## For running it

The ones the front page prints. Each does something a person running PPortal might want, and
none of them needs a checkout. `--consoles` is what running it with no flag at all does; it is
named here because a run that asked for a diagnostic screen instead can ask for this one back.

## For working on the tree

The rest report on this repository rather than on the console. They are the reason this area
exists: they are documented nowhere a reader could reach, and `--help` is a line each.

<HostFlags audience="maintainer" />

Two of them are worth naming here, because they are part of how work is committed rather than
diagnostics you run once:

- `--recount` checks every size the backlog states against the files it states them about, and
  prints the `roadkeep` call that corrects each. It writes nothing itself.
- `--ratchet` lists the shipped tasks that no assertion mentions. The count may fall and may
  not rise, so a task shipped with no test naming its id turns the suite red in the commit that
  ships it.

Both refuse rather than answer when the host running them is older than `app/`, and name the
source that moved. There is more than one `ChiakiNg.exe` on a machine that has built this tree —
`compile.cmd` builds one and prints where, and a publish leaves another behind — and a stale copy
reads the current backlog with rules the tree has moved past, which is a wrong answer that looks
exactly like a right one. Run the host `compile.cmd` names.
